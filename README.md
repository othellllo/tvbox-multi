# TVBox 多仓源（自建 + 自检）

> 2026-11-14 构建 · 6 个仓库可用、全部 jar 校验通过 · 单仓 127 站 / 66 解析

## 文件

| 文件 | 用途 |
| --- | --- |
| `tvbox-multi.json` | **多仓索引**（推荐）。App 里可以切 6 个仓库，死一个换一个 |
| `tvbox-single.json` | **单仓聚合**。127 站一步到位：短剧 4 + 动漫 4（以上来自主干）+ 26 个免 jar 的 api 站，66 个解析 |
| `tvbox-lite.json` | **精简版**。27 个纯 api 直连站，不用 jar，最不容易坏 |
| `config/sources.json` | 源注册表，想加源/换地址改这里 |
| `build.py` | 构建 + 体检脚本，一条命令重新生成上面三个文件 |
| `status.json` | 最近一次体检结果 |

## 怎么用

**方式一：有网址（推荐，能长期用）**
把整个目录传到你自己的 GitHub 仓库，然后：

- 多仓地址 `https://cdn.jsdelivr.net/gh/你的用户名/仓库名@main/tvbox-multi.json`
- 单仓地址 `https://cdn.jsdelivr.net/gh/你的用户名/仓库名@main/tvbox-single.json`

粘到 TVBox / 影视仓 / OK影视 的「设置 → 配置地址」即可。jsDelivr 在国内基本直连。
`.github/workflows/build.yml` 已配好：每天自动跑一次体检并提交结果，坏源自动从多仓里摘掉。

**方式二：本地文件**
把 `tvbox-multi.json` 放到手机上，用 App 的「本地配置 / 导入文件」选择它（影视仓、部分 TVBox 分支支持）。
如果导入报错，说明这个版本只认网址，走方式一。

**方式三：直接用现成的公共多仓**
懒得托管就先用 `http://ztha.top/TVBox/GYCK.json`（32 个子仓，实测可用），
它和本项目是同一路子，只是没有分类整理。

## 你要的分类在哪

| 分类 | 覆盖情况（实测站点数） |
| --- | --- |
| 电影 / 电视剧 / 综艺 | 6 个仓库全覆盖；单仓里另有 26 个 api 直连站（电影天堂、耐看、南柯、555 等） |
| 动漫 | 高天流云 14、老刘备 5、王二小 4、小盒子 3、挺好 3、小马 2 |
| 短剧 | 王二小 4（🍉好看/小猫/星星/小薇）、老刘备 4（🎧刷刷/BiL/葡萄/嗷嗷）、小盒子 1（🎭csp_Duanju） |
| AI 短剧 | 短剧站内有「AI 短剧」分类，选上面的短剧站就能看到，没有单独的仓库 |
| 红果短剧 | **公开 TVBox 源里没有官方红果接口**（我扫了 4 个大仓，`红果` 关键词 0 命中）。要看红果原生内容：用官方「红果短剧」App，或开源项目 [菲凡聚合](https://juejin.cn/post/7707184266061316130)；短剧站里也能搜到被搬运的红果/番茄系内容 |

## 长期怎么保证不失效

1. 隔一两个月在手机上跑一次：`cd 这个目录 && python3 build.py`
   它会重新拉全部源、校验 jar 的 md5、把死掉的源从多仓里去掉，重新生成三个 json。
2. 某个源彻底死了：打开 `config/sources.json`，把它的新地址填进 `urls` 数组（第一个失败会自动试第二个），或者 `"enabled": false` 停用。
3. 想加新源：在 `sources.json` 里照抄一段，`role` 填 `supplement`（默认）就能进多仓；填 `base` 会当单仓主干。
4. 托管在 GitHub 上的话不用管，Actions 每天自动跑。

> 多仓的意义就是「不把鸡蛋放一个篮子」：哪个仓库当天挂了，在 App 里切另一个仓库就行。
